### 38.5 ROM tables

The ROM table is a CoreSightTM component that contains the base addresses of the
CoreSight debug components accessible via the access port to which it is attached. These
tables allow a debugger to discover the topology of the CoreSight system automatically.

There is one top level ROM table behind each access port, APn. The base address of this
ROM table can be obtained by reading the APn_BASE register of the access port. The top
level ROM table may point in turn to other ROM tables.

The system ROM table is pointed to by the AP1 base register, AP1_BASE. It contains the
base address pointer for the DBGMCU.

The system ROM table occupies a 4-Kbyte, 32-bit wide chunk of the AP1 address space,
from 0xF000 0000 to 0xF000 0FFC. It can be accessed by the debugger.

**Table 249. System ROM table**

| Address offset in ROM table | Component name      | Component base address | Component address offset | Size (Kbytes) | Entry         |
| --------------------------- | ------------------- | ---------------------- | ------------------------ | ------------- | ------------- |
| 0x000                       | DBGMCU              | 0xF000 1000 (debugger) | 0x0000 1000              | 4             | 0x0000 1003   |
| 0x004                       | Top of table        | -                      | -                        | -             | 0x0000 0000   |
| 0x008 to 0xFC8              | Reserved            | -                      | -                        | -             | 0x0000 0000   |
| 0xFCC to 0xFFC              | ROM table registers | -                      | -                        | -             | See Table 252 |

There are two ROM tables in the CPU subsystem. The MCU ROM table is pointed to by the
AP0 base register, AP0_BASE. It contains the base-address pointer for the processor ROM
table.

The MCU ROM table (see the table below) occupies a 4-Kbyte, 32-bit wide chunk of the
AP0 address space, from 0xF000 0000 to 0xF000 0FFC. It is not accessible by software.

**Table 250. MCU ROM table**

| Address offset in ROM table | Component name      | Component base address | Component address offset | Size (Kbytes) | Entry         |
| --------------------------- | ------------------- | ---------------------- | ------------------------ | ------------- | ------------- |
| 0x000                       | Processor ROM table | 0xE00F F000            | 0x0000 1000              | 4             | 0xF00F F003   |
| 0x004                       | Reserved            | -                      | -                        | -             | 0x0020 0002   |
| 0x008                       | Reserved            | -                      | -                        | -             | 0x1000 0002   |
| 0x00C                       | Reserved            | -                      | -                        | -             | 0x1000 0002   |
| 0x010                       | Top of table        | -                      | -                        | -             | 0x0000 0000   |
| 0x014 to 0xFC8              | Reserved            | -                      | -                        | -             | 0x0000 0000   |
| 0xFCC to 0xFFC              | ROM table registers | -                      | -                        | -             | See Table 253 |

The processor ROM table contains the base-address pointer for the system control space
(SCS) registers that allow the debugger to identify the CPU core, as well as for the BPU,
DWT.
